2
💻 把贩卖机写成代码
爸爸
看，这就是一台"贩卖机函数"：
给它钱，它给你饮料！
def 贩卖机(钱):
    # 内部魔法：根据钱的数量，选不同的饮料
    if 钱 >= 5:
        return "🍊 橙汁"
    elif 钱 >= 3:
        return "💧 矿泉水"
    else:
        return "❌ 钱不够，退给你"

# 使用贩卖机
饮料 = 贩卖机(5) # 投5块钱
print(饮料) # 🍊 橙汁
啵啵
哦！`def` 就是"造一台贩卖机"，
`return` 就是"出货口"，
括号里的 `钱` 就是"投币口"！
📝 函数的三个"口"：
投币口 = 参数（输入）
内部机器 = 函数体（处理逻辑）
出货口 = return（输出）

🧠 深入内存：函数调用时，电脑在干什么？
🔬 深入底层 便签纸的比喻

想象你有一叠便利贴。每次调用函数，就像：
1️⃣ 拿出一张新便利贴（这叫"栈帧"）
2️⃣ 在这张纸上写下参数（投了多少钱？）
3️⃣ 在这张纸上打草稿（局部变量的计算）
4️⃣ 算出结果，把结果交出去（return）
5️⃣ 这张便利贴被撕掉扔掉（函数结束，内存释放）

电脑内存
来看看调用 贩卖机(5) 时，
内存里那张"便利贴"上写了什么：
📋 栈帧（Stack Frame）—— 贩卖机(5) 的工作台
🟠 贩卖机 的便利贴
📥 参数区：钱 = 5
📝 局部变量区：（这次没有局部变量）
📤 返回值区："🍊 橙汁"
📍 返回地址：调用者的下一行代码
函数执行完 → 返回值交给调用者 → 整张便利贴被销毁 🗑️
⬇️
5
📚 函数调用函数：便利贴叠罗汉！
爸爸
如果一个函数调用另一个函数呢？
就像大任务分成小任务，
每个小任务都需要自己的便利贴！
def 找零钱(支付金额, 价格):
    # 这张便利贴上计算找零
    找零 = 支付金额 - 价格
    return 找零

def 买饮料(饮料名, 支付金额):
    # 这张便利贴上处理购买逻辑
    价格表 = {"橙汁": 5, "矿泉水": 3}
    价格 = 价格表[饮料名]
    找零 = 找零钱(支付金额, 价格) # 调用另一个函数！
    return f"给你{饮料名}，找零{找零}元"

# 调用买饮料
结果 = 买饮料("橙汁", 10)
电脑内存
这时便利贴会叠起来（这叫"调用栈"）：
📚 调用栈（Call Stack）—— 便利贴叠罗汉

🟡 第2层：找零钱(10, 5) 的便利贴
📥 支付金额=10, 价格=5
📝 找零 = 5
📤 返回：5
⏳ 正在执行...执行完就撕掉
⬆️ 压在下面
🟠 第1层：买饮料("橙汁", 10) 的便利贴
📥 饮料名="橙汁", 支付金额=10
📝 价格表={...}, 价格=5
📤 等待找零钱()返回结果...
⏸️ 暂停等待

规则：最上面的便利贴先执行完，撕掉，然后下面那张继续。
🗼 调用栈 = 便利贴叠罗汉
新函数调用 → 新便利贴压在上面
函数执行完 → 顶部的便利贴被撕掉（这叫出栈）
所有便利贴用完 → 程序结束
⬇️

🫥 为什么函数里的变量，外面看不见？
啵啵
爸爸，我有个问题：
函数里面定义的变量，
为什么在外面就"消失"了？
爸爸
因为便利贴被撕掉了呀！
函数里面的变量是写在那张便利贴上的，
函数一结束，整张便利贴被销毁，
上面的东西自然就没了！
def 我的函数():
    秘密 = "我在这张便利贴上"
    print(秘密) # ✅ 函数内部可以访问
    return 秘密

结果 = 我的函数() # 返回值被保存到"结果"变量
print(结果) # ✅ 返回值被保存下来了
print(秘密) # ❌ 报错！便利贴已经撕掉了，秘密不存在了！
🔬 深入底层 作用域与内存管理

这叫"局部作用域"（Local Scope）——函数内部是一个独立的小世界。

🗑️ 函数结束 → 栈帧销毁 → 局部变量消失 → 内存被自动回收
这其实是好事！想象一下，如果每次用完的便利贴都不扔，你的桌子早就堆满了！

只有 return 的值能被"传递"到外面——就像你把便利贴上的答案抄到一张永久保存的纸上。

🎯 局部变量的宿命：
生：函数被调用时诞生在栈帧上
活：函数执行期间发挥作用
灭：函数 return 后随栈帧一起销毁
💡 只有 return 的值能"逃出去"！
⬇️

🗺️ 变量的"住处"：栈 vs 堆
爸爸
啵啵，变量其实有两种"住处"：
一种是"栈"——便利贴，用完就扔
一种是"堆"——大仓库，长期存放
📋 栈（Stack） 🏭 堆（Heap） 啵啵的类比 便利贴——用完就扔 大仓库——东西放很久 存放什么 局部变量、函数参数 对象、大块数据 生命周期 函数调用时创建，返回时销毁 手动删除或垃圾回收才消失 大小 小（几MB） 大（可以很大） 速度 ⚡ 非常快 🐢 相对慢 管理方式 自动（函数结束自动释放） Python 的垃圾回收器管理
🔬 深入底层 为什么要有栈和堆的分离？

栈的好处：非常快，而且自动清理。函数调用完，栈帧直接弹出，不用操心内存。

栈的局限：只能放"知道大小的东西"。如果一个列表会不断变长，栈就放不下了——这时候就需要堆。

堆的好处：可以放"大小会变"的东西（列表、字典、对象），生命周期灵活。

Python 的贴心之处：大多数时候你不需要关心这些，Python 的垃圾回收器会自动打扫堆上的垃圾。

⬇️

💥 如果便利贴贴满整张桌子呢？
爸爸
如果函数一直调用自己（这叫递归），
而且忘了停下来...
便利贴就会无限叠上去，直到桌子塌了！
def 无限递便利贴():
    return 无限递便利贴() # 调用自己，永远不停！

# 运行这行代码会...
无限递便利贴()
# RecursionError: maximum recursion depth exceeded
# 翻译：便利贴贴太多啦！桌子塌啦！（栈溢出）
💥 栈溢出（Stack Overflow）

🟥 第1000层便利贴：无限递便利贴()
⋯⋯
🟥 第3层便利贴：无限递便利贴()
🟥 第2层便利贴：无限递便利贴()
🟥 第1层便利贴：无限递便利贴()
⚠️ 桌子只能放1000张便利贴，第1001张放不下了！
💥 桌子塌了！（栈溢出错误）
⚠️ Stack Overflow（栈溢出）= 便利贴贴满桌子塌了
这也是那个著名编程问答网站的名字由来！
每次函数调用都消耗一点栈空间，无限递归就会撑爆。
